# Markdown 转公文式 Word

## 两阶段，顺序不可颠倒

```
阶段一 润色   Markdown → 公文语体的 Markdown
阶段二 转换   公文语体 Markdown → docx（调用 scripts/render_docx.py）
```

**先润色后转换。** 直接跑脚本只会把口语段落原样排进公文版式——格式对了，读起来还是内部草稿，这不叫转换。样例那份报告之所以读起来像正式文件，一半在版式，一半在语体。

---

## 阶段一：润色成公文语体

目标语体取自公司模板《2026绿化养护面积核准报告(格式统一版)》。它有以下可测量的特征：

| 特征 | 样例实测 | 润色要求 |
|---|---|---|
| 段落长度 | 25 个正文段落，平均 69 字，中位 66 字 | **单段 40–120 字**，超过 150 字拆段 |
| 段落开头 | 无连接词堆叠，直接陈述事实或判断 | 段落首句即结论或事实，不写「接下来」「首先我们来看」 |
| 人称 | 全文 0 处「我们 / 我司 / 本人」 | **零第一人称**。用「公司」「本项工作」或无主语句 |
| 口语词 | 0 处「搞定 / 弄 / 其实 / 非常 / 特别」 | 全部清除 |
| 模糊词 | 「基本 / 大致 / 差不多」仅 1 处 | 能给数字就给数字，给不了用「约」并注明口径 |
| 感叹/强调符号 | 0 处 `!！` | 不用感叹号。**加粗也只在封面标题保留** |
| 数字 | 60 处带单位（㎡ / 元 / % / 处） | 每个数字带单位与口径 |
| 分号并列 | 8 处 | 多个并列事实用分号串成一句，不拆成多行 |
| 枚举 | 「一是…二是…三是…」「此外」「其中」「另有」 | **用这些词做层级**，不用 Markdown 的 `-` 列表 |
| 引用数据表 | 「详见表1、图1」 | 正文提一次表号/图号即可，不展开表格内容 |

### 润色动作清单

1. **删列表符号。** `- xxx` / `1. xxx` 改写成「一是…二是…三是…」「1. …2. …」的正文段落。样例里没有一处 Markdown 项目符号。
2. **拆长段。** 一段只说一件事。标题下的导语一句话：「按养护单位归集原有统计面积与标注核准面积，其增减情况详见表1、图1。」
3. **改人称与语气。** 「我们需要」→「需」；「我们建议」→「建议」；「我算了一下」→ 直接给结论和口径。
4. **数字补口径。** 「便宜了 1 万多」→「较原方案减少 1.2 万元以上（原方案年度费用约 6.6 万元，本次实付 53,794.38 元）」。
5. **加边界说明段。** 凡是数据有估算或口径差异，单独起一段以「说明：」开头，写清误差来源与以什么为准——样例每处关键数据后都有这么一段。
6. **结论段编号化。** 最后一章用「1. 2. 3.」逐条写结论，每条一句话，可独立引用。

### 润色检查

```
grep -nE '我们|我司|本人|搞定|弄|其实|非常|特别|!|！' polished.md
```

有任何命中就继续改。**零命中才能进入阶段二。**

## 阶段二：转换为 docx

### 输入格式约定

```markdown
# 关于年度云服务器续费 | 与新增采购的请示      ← " | " 分隔封面两行标题

> 编制：王唯力
> 编制单位：无锡格物智能科技有限公司
> 编制日期：2026年11月

## 一、判断与建议                                ← 一级标题
### 6.1 代码只存于个人电脑与网盘的问题            ← 二级标题
正文段落……

| 服务器 | 承载业务 | 金额 |                      ← 表格，自动编号「表 N」
%% 表题：存量服务器续费清单                      ← 可选，表题文字

```mermaid
...
```
%% 图题：新平台服务拓扑与新增服务器定位            ← 可选，图题文字
```

### 执行

```bash
# 1. 图：把 mermaid 渲成白底黑线 PNG（先写主题配置，见 references/mermaid-white-theme.json）
npx -y -p @mermaid-js/mermaid-cli mmdc -i figure.mmd -o figure.png -b white -s 3 -c mermaid-white-theme.json

# 2. 生成 docx
python3 scripts/render_docx.py polished.md 输出.docx --figure figure.png
```

`--figure` 省略时使用 `template/media/figure.png` 占位图。

### 版式规格（脚本已内置，改动前先看 references/layout-spec.md）

| 元素 | 规格 |
|---|---|
| 纸张 / 页边距 | A4；上 2.8cm、下 3.2cm、左右 2.5cm |
| 正文 | 方正仿宋_GB2312 16pt，固定行距 30pt，首行缩进 2 字符 |
| 一级标题 | 方正黑体 16pt，`heading 1` 样式，首行缩进 2 字符 |
| 二级标题 | 方正楷体 16pt，`heading 2` 样式 |
| 封面标题 | 方正小标宋 36pt 加粗居中，封面单独一页 |
| 封面信息 | 方正楷体 22pt 居中，三行：编制 / 编制单位 / 编制日期 |
| 目录 | 楷体 16pt，点线引导到右边界，超链接 + PAGEREF 域 |
| 表格 | 9751 twips 居中，全框线，仿宋 10.5pt，首行加粗重复 |
| 表题 / 图题 | 黑体 9pt 居中，格式「表 N　题名」「图 N　题名」，**紧贴对象，中间不留空段** |
| 页脚 | 「— 1 —」灰色 8.5pt 居中 |
| 字体 | 三个 .odttf 随文档嵌入，并保留 altName 回退 |

## 交付前必须逐项验证

**不要凭「看起来对」交付。逐条实测：**

```bash
python3 - <<'EOF'
import zipfile, re
from xml.etree import ElementTree as ET
z = zipfile.ZipFile(OUT)
assert z.testzip() is None
for n in z.namelist():
    if n.endswith('.xml') or n.endswith('.rels'):
        ET.fromstring(z.read(n))          # 任何部件不可解析 => Word 会报修复
x = z.read('word/document.xml').decode()
print('分页符', x.count('<w:br w:type="page"/>'))       # 必须正好 2：封面后、目录后
print('表题', re.findall(r'表 \d+[^<]*', x))
print('图题', re.findall(r'图 \d+[^<]*', x))
print('目录域', x.count('HYPERLINK'), x.count('PAGEREF'))  # 两者必须相等且等于标题数
print('内嵌字体', [n for n in z.namelist() if n.endswith('.odttf')])  # 必须非空
EOF
```

| 检查项 | 通过标准 |
|---|---|
| zip 完整性 | `testzip()` 返回 None |
| XML 可解析 | 所有 `.xml` / `.rels` 部件都能 `ET.fromstring` |
| 分页 | 恰好 2 个分页符 |
| 表题 / 图题 | 每个表格、图片上方都有「表 N」/「图 N」，且**紧贴对象，中间无空段落** |
| 目录 | HYPERLINK 与 PAGEREF 成对，数量等于各级标题总数 |
| 字体 | `word/fonts/*.odttf` 存在至少 3 个 |
| 封面 | 封面段落数 × 30pt < 23.7cm（A4 可用高度），否则会溢出到第二页 |
| 图片 | PNG 魔数正确（`\x89PNG`），插入尺寸与原图比例一致 |

**只验证 XML 结构不算通过。** 必须检查字体是否内嵌、分页符数量、题注位置这类会让老板一眼看出毛病的东西。

## 常见失败与对策

| 现象 | 根因 | 对策 |
|---|---|---|
| 打开全是方块/乱码 | 只复制了样式表，没复制 `.odttf` 字体文件；或文档级 `rFonts` 用主题引用 | 保留 `template/word/fonts/*.odttf`，每个 run 显式写 `w:eastAsia="字体名"` |
| 第二页是空白页 | 封面末尾多放了分页符，或目录末尾多放空段落 | 分页符只有 2 个；封面段落总数 × 30pt 必须 < 23.7cm |
| 表题和表格之间多一行 | 在题注和对象之间插了空段落 | 题注紧贴对象，不加空段 |
| 图变成一片空白框 | 用 `sips` 或截图工具把 JPEG 存成 `.png` 扩展名 | 检查 PNG 魔数；Mermaid 用 `mmdc -b white` 直接出 PNG |
| 图被压扁 / 撑破版面 | 插入尺寸直接写死，没按原图比例 | `cx/cy` 必须等于 PNG 的宽高比；宽 9.7cm 左右可让竖版图单页放下 |
| 目录页码全是 1 | PAGEREF 域没有更新 | 交付时说明：右键目录 →「更新域 → 更新整个目录」 |
| 页面显示为方块但字体已嵌入 | 字体表缺 altName 回退 | 在 `fontTable.xml` 为每个中文字体补 `<w:altName w:val="系统上有的同族字体"/>` |

## 测试中暴露的高频偏差（务必自查）

以下偏差来自「不给技能 vs 给技能」的对照实测。前四条是不给技能时的典型失败，后三条是给了初版技能后仍然出现的。

| 偏差 | 表现 | 修正 |
|---|---|---|
| **照抄源文档的章节标题** | 标题写「摘要」「背景与现状」这类内部提纲语 | 改公文式：「一、采购概况」「二、判断与请示建议」。样例从不用「摘要」当章名 |
| **难看地拆句** | 每段都拆成 6–20 字的碎句，平均 45 字，中位 30 字 | 样例平均 **69 字、中位 66 字**。**目标 60–90 字一段**，不要拆碎 |
| **重复源文档的结构加造表** | 凭空新增「表 1 采购金额构成」等源文档里没有的表 | 只把源文档已有的信息整理成表；不新增数据维度 |
| **保留源文档的口语标题与自造词** | 如「本次采购事项的判断与建议如下」这类引出句 | 段落直接进入事实，不加「如下」式引出语 |
| **图题放错方向** | 图题放在图**上方** | 样例是**图题在图下方**、表题在表上方。方向反了就是格式不对 |
| **图片尺寸写死** | 用固定 `cy`，与 PNG 实际比例不符，图被压扁 | 读 PNG 头取宽高比，`cy = cx * h / w` |
| **字体缺 altName 回退** | 只嵌字体不给回退名，目标机器缺字体时仍可能替换成方块 | 为每个中文字体补 `<w:altName>`，模板已在脚本中自动补 |

## 边界

- **不臆造内容。** 润色只改表达，不改数字、不改结论、不补用户没说的事实。缺数据就保留「待确认」。
- **不覆盖源文件。** 输出写到新文件名，源 Markdown 保持原样。
- **图必须来自 Mermaid 或其他真实渲染**，不能用手画近似图替代。
- 模板中的字体若目标机器没有安装，依靠内嵌字体与 altName 回退；两者都失败时，把字体族换成「宋体 / 仿宋 / 黑体 / 楷体」重新生成，字号行距不变。
