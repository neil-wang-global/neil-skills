# 场景模板

四个场景选一个用。**所有模板共用同一套六段逻辑**，只是权重不同。

---

## 通用骨架

```
# [结论式标题：动作 + 对象 + 请示性质]

## 摘要
（8 行内。要什么 / 值多少 / 花多少 / 何时答复）

## 一、判断与建议
## 二、背景与现状
## 三、方案与预期
## 四、投入与周期
## 五、风险与应对        ← 仅在真实风险存在时保留，否则删除（见 SKILL.md 6.3）
## 六、请示事项
附件（仅放老板要核对的凭证，不放他要读的文档）
```

**"一"是最重要的一段，先答"你要我做什么"。** 后面几段是证据。

---

## 模板 A：立项申请（要钱 / 要人 / 要大改）

**权重：Why 和 请示最重。必须有"不做"对比。**

```
## 摘要
建议 [做什么]。需投入 [钱/人/周期]，预计 [关键收益]。
请于 [日期] 前审批，否则 [具体后果]。

## 一、判断与建议
建议实施 [项目名]。理由：[一句话核心逻辑]。
需增配 [资源]，周期 [区间]。若不实施，[具体代价]。

## 二、背景与现状
[老板已经感知到的现象，带数字和时点]
[用类比说明结构性问题，不用技术术语]

## 三、方案与预期

| 维度 | 现状 | 实施后 |
|---|---|---|
| 收入 | | |
| 成本 | | |
| 风险 | | |
| 效率 | | |

## 四、投入与周期
| 项目 | 数量 | 说明 |
|---|---|---|
| 人力 | | |
| 周期 | [区间]，以 [前置条件] 为约束 | |
| 采购 | | |

## 五、风险与应对
最多三条。每条：风险 → 我将如何应对 → 止损条件。

**最坏情况**：[写清楚。不写，老板不信]。

### 方案对比
| 选项 | 投入 | 效果 | 风险 |
|---|---|---|---|
| A（推荐） | | | |
| B | | | |
| 不做 | 0 | 无改善 | [隐性成本，量化] |

## 六、请示事项
| # | 请示 | 截止 | 不批的后果 |
|---|---|---|---|
```

**"不做"这一列是说服力最强的一列。必须量化它的隐性成本。**

## 模板 B：进度汇报（阶段同步）

**权重：结论 + 风险变化 + 需要协调什么。一页内。**

```
# [项目名] 进度汇报 —— [正常 / 有风险 / 需支援]

## 摘要
[现在什么阶段，最重要的一个变化。一句话说完。]

## 一、总体判断
[正常推进 / 存在风险，风险为……]

## 二、本期进展
| 事项 | 计划 | 实际 | 状态 |
|---|---|---|---|

**关键变化**：[和上期相比，什么变了]

## 三、风险与应对
只写有变化的。没变化就写"风险无变化"。

## 四、请示事项
[只写真正需要老板的。没有就写"本次无需您决策，仅供知悉"。]
```

**没有需要老板做的事时，不要硬编一个请求。** 写"仅供知悉"是专业，不是失职。

## 模板 C：事故复盘

**权重：先担责，再讲原因，重点是如何避免再犯。**

```
# [事件] 复盘报告

## 一、我的责任
[第一句就承认管理责任。不要用"由于……导致"开头。]

## 二、事件经过
| 时间 | 事件 |
|---|---|

影响：[多少用户 / 多久 / 损失多少]

## 三、根因
[层层追问，但最终落到一句老板能懂的话]

## 四、已采取的止血措施
- 

## 五、如何避免再发生
| 措施 | 负责人 | 完成时间 | 如何验证有效 |
|---|---|---|---|

## 六、请示事项
[需要老板支持的：增加投入 / 调整流程 / 跨部门协调]
```

**复盘的核心不是解释"为什么不是我的错"，而是证明"下次不会再有"。** 老板要的是安全感，不是真相。

## 模板 D：年度 / 季度规划

**权重：与业务目标对齐，讲清钱花在哪。**

```
# [年份] 技术投入规划

## 一、判断与建议
[明年技术投入的总盘子、三个重点、要老板批的总额]

## 二、与业务目标的对应关系
| 业务目标 | 技术如何支撑 |
|---|---|

## 三、投入结构
| 类型 | 占比 | 说明 | 对应目标 |
|---|---|---|---|
| 保命（稳定/安全/合规） | | 不做会出事 | |
| 提效（省成本/提速度） | | 直接省钱省时间 | |
| 增长（支撑新业务） | | 支撑收入增长 | |

**"保命 / 提效 / 增长"三分法，老板立刻能理解钱为什么要这么花。**
```

## 通用：请示事项的写法

**默认只报一个方案。**

```
请于 [日期] 前批准 [金额/事项]，并确认执行方式：[步骤一] → 完成后立即 [步骤二]。

若逾期未批：[具体后果]。
```

方案细节你比老板清楚，**给他出选择题等于把决策难度退回去**。

**只有两条路径真的代表不同的钱、不同的人或不同的风险时**，才给选项，且必须标出推荐项：

```
需要您于 [日期] 前选择：

A. [方案] —— 建议采用。理由：[一句]
B. [方案] —— 代价：[一句]

不决策的影响：[具体后果]
```
